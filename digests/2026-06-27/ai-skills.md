## Skills 社区热点报告 (2026-06-27)

### 1. 热门 Skills 排行 (Pull Requests)

**1. skill-creator 工具链修复 (PR #1298, #1323, #1099, #1050)**
- **功能**：针对 `skill-creator` 工具集（`run_eval.py`, `run_loop.py`, `improve_description.py`）的一系列修复，重点解决 **`recall=0%`** 和 **Windows 兼容性**两大核心问题。
- **讨论热点**：多个 PR 都指向同一个核心故障：`run_eval.py` 无法正确检测技能是否被触发，导致优化循环（`run_loop.py`）在“噪音”中寻找最优描述，结果永远是 `recall=0%`。修复方案涉及技能安装逻辑、触发检测机制、子进程管道读取以及 Windows `PATHEXT` 处理等多个方面。
- **当前状态**：均为 OPEN。该系列 PR 是当前仓库最活跃的讨论焦点，表明工具链本身的稳定性是社区贡献者的首要痛点。

**2. 文档排版技能 (document-typography) (PR #514)**
- **功能**：为 AI 生成的文档添加排版质量控制，防止如单词悬垂、标题孤行和编号错位等常见问题。
- **讨论热点**：该 PR 精准定位了 AI 文档生成中普遍存在但用户很少主动报告的细节质量问题，讨论集中在这些“不为人知但烦人”的排版 bug 对用户体验的长期影响。
- **当前状态**：OPEN。

**3. ODT 文档技能 (PR #486)**
- **功能**：支持创建、填充、读取和转换 OpenDocument 格式文件 (.odt, .ods)，包括 LibreOffice 文档和 ISO 标准格式。
- **讨论热点**：反映了用户对除 PDF 和 DOCX 之外的开源办公文档格式的支持需求。讨论可能围绕其模板填充能力以及与现有文档技能的协同。
- **当前状态**：OPEN。

**4. 全栈应用部署技能 (AppDeploy) (PR #360)**
- **功能**：允许 Claude 通过 [AppDeploy](https://appdeploy.ai/) 服务直接部署和管理全栈 Web 应用。
- **讨论热点**：该技能将 AI 的能力从“代码生成”扩展到“服务部署”，代表了更完整的开发流程闭环。讨论可能关注其安全性、部署限制以及与现有托管服务的集成。
- **当前状态**：OPEN。

**5. 测试模式技能 (testing-patterns) (PR #723)**
- **功能**：提供一个全面的测试技能，涵盖测试理念（如“奖杯”模型）、单元测试、React 组件测试、集成测试和端到端测试模式。
- **讨论热点**：该技能试图统一并标准化 Claude 的测试行为。讨论可能围绕不同测试框架的选择、模式的具体实现细节以及社区的采纳程度。
- **当前状态**：OPEN。

**6. 代码库清单审计技能 (codebase-inventory-audit) (PR #147)**
- **功能**：提供一个系统化的 10 步工作流，用于识别孤立代码、未使用文件、文档缺口和基础设施膨胀，最终生成一个 `CODEBASE-STATUS.md` 文件。
- **讨论热点**：该技能专注于代码库健康度和可维护性，是一个典型的“开发者体验” (DevEx) 类技能。讨论可能围绕其工作流的完整性以及在实际大型项目中的运行效率。
- **当前状态**：OPEN。

### 2. 社区需求归类 (Issues)

- **安全与信任** (Issue #492)：社区对“信任边界滥用”表达了严重关切。问题在于社区技能被放入 `anthropic/` 命名空间下分发，可能误导用户授予其凭据。这是生态建设中关于认证、安全和用户信任的极早期信号。
- **组织级共享** (Issue #228)：用户强烈希望能在组织内部直接共享技能，而非通过手动下载和聊天工具传输。这指向了企业采用场景下的一个关键功能和协作需求。
- **工具链稳定性** (Issue #556, #1169, #1061)：大量 Issue 反馈了 `skill-creator` 工具链的严重 bug，主要集中在 `recall=0%`（无法正确评估技能质量）和 Windows 兼容性失败。这是当前社区最直接、最强烈的技术瓶颈。
- **技能生态拓展方向**：
  - **智能体治理** (Issue #412)：提出面向智能体系统的安全模式，包括策略执行、威胁检测和审计跟踪。这是一个面向未来的、在智能体复杂度上升时必然面临的需求。
  - **持久化记忆** (Issue #1329)：提出“compact-memory”技能，通过符号化表示来压缩智能体的长期记忆，节省上下文窗口。反应了在大上下文场景下对知识管理效率的追求。
  - **MCP 化** (Issue #16)：建议将 Skills 的能力以模型上下文协议 (MCP) 的形式暴露为标准 API。这是一个关于 Skills 未来架构和可组合性的前瞻性需求。
