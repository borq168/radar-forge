## 5. 差异化定位分析

- **功能侧重**
  OpenClaw 定位为通用 AI 代理平台，提供多通道（Telegram、WhatsApp、macOS Quick Chat 等）、自动化和原生编码会话，以及丰富的工具链和权限模型。
  LobsterAI 侧重协同工作（cowork）与服务部署的数据持久化，界面服务于团队协同 AI 任务，当前日报反映的核心改进是错误 UI 展示和部署持久化，未出现通道、自动化等能力。

- **目标用户**
  OpenClaw 面向个人开发者、团队自建代理和高级用户，强调高度可定制和跨平台体验。
  LobsterAI 更像面向企业或团队的 AI 协作平台，用户关注服务部署稳定性和协同过程中的错误可见性。

- **技术架构关键词**
  OpenClaw 涉及 Codex、远程会话、内存回忆、SQLite 迁移、心跳驱动代理等底层机制。
  LobsterAI 的代码提及协同 UI、服务部署数据持久化、MCP（OpenClaw 引擎集成）等，MCP 集成依赖 OpenClaw 引擎也从侧面反映其架构可能复用或依赖 OpenClaw 基础组件。

   多个用户明确报告长图崩溃、配置编辑失效等问题，但均因 stale 标记被机器人关闭，无任何维护者交互，导致用户问题悬而未决超过3个月，实质积压被自动化规则隐藏。

   Quick Chat 增强、Linux/Windows 应用呼声（#75，113 评论，81 👍）、Telegram 各类缺陷持续获得反馈，说明桌面和消息通道的体验提升是长期且强烈诉求。

4. **LobsterAI 的 MCP 集成受到底层引擎限制影响**
   用户自定义 HTTP MCP 在 OpenClaw 引擎中不生效的问题（#1293）被长期搁置，表明其对外部工具链的扩展性受制于所集成引擎的能力边界，且项目侧无解决方案。

5. **OpenClaw 的修复吞吐量虽高，但高严重度 Bug 收敛存压**
   同一天内出现多个 P0/P1、涉及 Codex 消息丢失和工具中断等问题，且部分没有已链接的修复 PR，表明新功能并跑的过程中，关键路径稳定性仍面临较高不确定性。

## 7. 用户反馈摘要
从近期 Issues 中提取的真实痛点：
- **MCP 标准支持不全**：用户期望 `http` 类型自定义 MCP 能与 SSE 一样被引擎加载，否则自建工具无法融入现有工作流。
- **图片解析鲁棒性不足**：普通上传长图即引发全局性崩溃，且无错误恢复机制，严重影响使用信心。
- **上下文限制误判**：正常短输入被指“内容过长”，用户无法理解判断依据，配置调试成本高。
- **配置编辑交互反直觉**：关闭面板后另一配置变只读，导致用户以为是数据损坏，反复刷新页面。
- **任务生命周期管理不完善**：删除定时任务后历史记录标题不配套，引发数据一致性疑虑。

满意度方面，反馈多为 Bug 报告，不涉及对现有功能的好评或差评，仅表达受阻情绪。
